# Примеры оценки

Примеры показывают калибровку. Полный JSON всегда содержит все 32 критерия; сокращённые фрагменты ниже не являются готовым вводом калькулятора.

Во всех числовых примерах scope manifest создан из реальных файлов, content hashes сверены через `--root`, а общий digest соответствует цели, версии, units и исключениям.

## Надёжный runbook — 92/100

Область: `deploy.md` версии `v3.2`, роль `core`, профиль `runbook`. Все источники доступны.

| Измерение | Балл | Причина потери |
|---|---:|---|
| Полномочия и область | 15/15 | — |
| Корректность и проверяемость | 13,5/15 | Актуальность окружения подтверждена частично |
| Полнота сценариев | 13/15 | Граничный сценарий частичного отката описан не полностью |
| Согласованность | 15/15 | — |
| Исполнимость | 15/15 | — |
| Структура и навигация | 9/10 | Второстепенный путь находится только через поиск |
| Сопровождаемость | 7,5/10 | Команда продублирована; владелец обновления указан частично |
| Ясность и доступность | 4/5 | Одно сокращение не определено |

Системных ограничений нет. Нижняя и верхняя границы совпадают: `92/100 — эталонная — высокая уверенность`.

## Противоречивый набор правил — 39/100

Область: `AGENTS.md` и `DOCS.md` одной версии, роли `authority`, профиль `instruction`.

- `AGENTS.md`, `§ Editing`: изменение разрешено.
- `DOCS.md`, `§ Protected files`: то же изменение запрещено.
- Оба правила применимы и не определяют приоритет.

Сумма критериев до ограничения — 67. Зарегистрирован один `critical_authority_conflict` с двумя различными локаторами и cap 39.

Расчёт: `min(39, 67) = 39`. Балл не уменьшается повторно штрафом. Итог: `39/100 — непригодная — высокая уверенность`.

Перед исправлением агент объясняет причину и запрашивает выбор: сделать `AGENTS.md` единственным owner разрешения либо сделать `DOCS.md` единственным owner запрета. Для каждого варианта он показывает, какие действия станут разрешены, какие ссылки нужно заменить и какое правило потеряет силу. До ответа score остаётся действительным, но редактура не начинается.

## Быстрая правка корневых инструкций

Пользователь явно требует переименовать `docs-rules.md` в `DOCS.md`, перенести `contracts/MODEL.md` в корень, создать `WORKFLOW.md` и сохранить удалённый текст. Применимых owners несколько нет, итоговая структура задана пользователем.

1. Выбрать быстрый режим, получить актуальный head целевой ветки и прочитать четыре файла один раз.
2. До замены сохранить фактические версии целевой ветки в non-authoritative `legacy/instructions/<date>/` и сверить blob/hash.
3. Одним проходом изменить `AGENTS.md → DOCS.md → MODEL.md → WORKFLOW.md`.
4. Один раз проверить ссылки, имена, placement, лимиты, противоречия и `git diff --check`.
5. Создать один commit в разрешённую target-ветку.

Не создавать semantic graph, `review.json`, line ledger, stage manifests или independent review: ни один из них не меняет решение в этом примере. Перейти в глубокую миграцию только если обнаружатся competing owner, неразрешимый precedence или routing cycle.

## Последовательное подключение контрактов

Контур содержит `AGENTS.md`, `docs-rules.md`, корневые `MODEL.md` и `WORKFLOW.md` и новый `contracts/artifacts.md`. Только `docs-rules.md` владеет правилами оформления документации.

1. Bounded inventory путей/frontmatter/H1/H2 подтверждает роли. До удаления старого пути весь `docs-rules.md` byte-exact сохраняется в `archive/instructions.jsonl`, проходит `verify`, затем переносится в корень как `DOCS.md`; ссылки и graph evidence обновляются. В `DOCS.md` добавляются canonical names, root placement, lowercase contracts и правило архива.
2. `AGENTS.md`, затем `DOCS.md` разбираются сверху вниз до `plan_stable`. Pending moves остаются в source; каждый удаляемый byte-span сначала добавляется через `archive_instruction_content.py`, проверяется и при выборочном контроле восстанавливается через `extract`.
3. Для каждого stage рабочий агент создаёт candidate delta, независимый агент подтверждает manual delta, затем выполняется `--migration-gate` до и после routing-link.
4. `MODEL.md` подключается из `DOCS.md`, затем так же подключается `WORKFLOW.md`.
5. Только после них добавляется `contracts/artifacts.md`. После target/routing gate исходное правило удаляется из parent, его hash и граф проверяются повторно, и parent становится `content_final`.
6. После всех contracts выполняются `--final-topology-gate`, итоговый clean-context review и correction pass; затронутые gates повторяются, затем замораживаются hashes и рассчитываются отдельные scores для связных целей.

Ни один удалённый фрагмент или старый файл не исчезает: JSONL archive хранит исходные байты в Base64, offsets, path, locator, content/record SHA-256, причину и replacement; hash chain и sidecar head обнаруживают перестановку/усечение. Archive имеет `artifact_kind=archive`, `authority: false` и не участвует в routing.

## Неполная спецификация — диапазон 64–72/100

Область документа полна, но реализация и provider-owned schema недоступны. Критерии стоимостью 8 баллов имеют статус `unknown`.

- подтверждённая нижняя граница: 64;
- потенциальная верхняя граница: 72;
- системных ограничений нет;
- уверенность средняя.

Итог: `64–72/100 — уровень неопределён — средняя уверенность`. Нельзя преобразовать диапазон в одну точку 68 и использовать её как доказанный release gate.

## Статусы критерия

`met` требует положительного evidence:

```json
{
  "status": "met",
  "rationale": "Область и владелец названы.",
  "evidence": [
    {
      "kind": "supports",
      "path": "docs/deploy.md",
      "locator": "§ Scope",
      "note": "Production и роль дежурного заданы явно."
    }
  ]
}
```

`partial` требует одновременно подтверждение и пробел:

```json
{
  "status": "partial",
  "rationale": "Полный откат есть, частичный отсутствует.",
  "evidence": [
    {
      "kind": "supports",
      "path": "docs/deploy.md",
      "locator": "§ Full rollback",
      "note": "Полный откат содержит команды и проверку."
    },
    {
      "kind": "gap",
      "path": "docs/deploy.md",
      "locator": "§ Rollback",
      "note": "Нет решения для частично применённой миграции."
    }
  ]
}
```

## Граф: кандидат не равен доказанному конфликту

Два правила нормализованы в одинаковый frame:

| Поле | Правило A | Правило B |
|---|---|---|
| subject | `agent` | `agent` |
| modality | `MUST` | `MUST` |
| polarity | `positive` | `negative` |
| action | `edit` | `edit` |
| object | `protected file` | `protected file` |
| condition | `explicit request` | `explicit request` |

Checker возвращает `normalized-rule-conflict` со статусом `candidate`. Ревьюер обязан проверить исходные spans, scope, исключения и precedence. Только после adjudication finding переносится в `cross_document_consistency`; cap `operational_contradiction` допустим лишь когда конфликт влияет на основной путь. Сам candidate не меняет 100-балльную оценку.
